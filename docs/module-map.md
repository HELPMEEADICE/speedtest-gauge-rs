# 模块对照表（module map）

本文件回答一个问题：**原 TypeScript 项目的每个文件，落在本 crate 的哪个文件里，以什么方式移植。**

口径（必须先统一）：

- 原始 TS 项目**不在本机**（另一仓库，未读）。本文所有关于原实现的陈述，均转引自本 crate 内的注释与文档，逐条标注出处。
- 本文里的"逐行等价"指本 crate 注释明确宣称"逐行等价移植 `xxx.ts`（全文 N 行）"；"语义等价"指行为/数值等价但实现手段改变；"有意偏离"指有据可查地主动不照抄；"新增扩展"指原项目没有对应物、为本 crate 运行时/自证需要而新增。
- 单位约定：uu = SVG 用户单位（`viewBox 0 0 286 286`，`src/lib.rs:57-58`）。

## 3. 结构说明

1. **数值层**（不含 UI，逐行等价 `src/gauge/*.ts`）：`geometry` `scale` `model` `gradient` `gradient_data` `animation` —— `src/lib.rs:4-5` 的原话是"数值层（逐行等价于原项目 `src/gauge/*.ts`，不含 UI）"。
2. **视图桥接**：`renderer`（uu → `Path.commands` / 环段表 / 指针烘焙 / 布局量）与 `gauge::GaugeHandle`（状态机 + 动画泵 + 属性推送），见 `src/lib.rs:6-7`；`renderer` 自身声明"不依赖 Slint 运行时（不构造 `ModelRc`），因此可单独单元测试"（`src/renderer.rs:5-6`）。
3. **组件层**：`ui/speed-gauge.slint`（286 uu 坐标系、纯矢量，`src/lib.rs:8`）+ `ui/demo.slint`（Demo 外壳，走 experimental 的 `ComponentContainer`）。
4. **自证工具**：`src/shots.rs`（无窗口软件渲染 → PNG，`src/lib.rs:9`）→ `examples/shots.rs` / `examples/invariance.rs`；数据侧的自证另有 `tests/golden/demo_samples.json`。
5. **数值层可脱离 Slint 单测**：`tests/geometry.rs`、`tests/scale.rs`、`tests/model.rs`、`tests/gradient.rs`、`tests/animation.rs`、`tests/demo_source.rs` 都只 import 数值层模块，不装任何 Slint 平台。
6. 需要 Slint 的只有 `tests/instances.rs`（3 个 `SpeedGauge` 同进程）与 `tests/snap_reset.rs`（`snap_to` 与归位交互），二者都自建 headless 平台；`tests/instances.rs:11-13` 说明"平台是**线程本地**的……所以每个测试线程各自装一次 headless 平台"。
7. `tests/needle_raster.rs` 落在中间：验证的是 `NeedleRaster::update()` 吐出的 RGBA，"不经过 Slint"（`tests/needle_raster.rs:3-4`），因此也属于数值层可测的范围。
8. 单向依赖：`model` / `geometry` / `scale` / `gradient` / `animation` 之间只有 `model`→`scale`、`gradient`→`geometry`、`animation`→`geometry`+`model` 这几条边（见各文件 `use` 段），**没有反向边**，所以渲染层可以整体替换而不动数值层。
9. 数据层是最外的一层：`data_source` 只依赖 `model::Stage`（`src/data_source.rs:26`），`demo_source` 只依赖 `data_source` + `model`，与 UI 无耦合 —— 这正是 `docs/real-backend.md` 能单独讲"怎么接真引擎"的前提。
