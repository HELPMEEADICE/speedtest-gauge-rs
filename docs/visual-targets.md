# 视觉锚点实测表（Visual targets）

本文件是 **Rust + Slint 端口与 `report/local-*.png` 对拍的唯一量化基准**。
所有数值都由 `tools/measure_reference.py` 从原始参考截图逐像素实测得到，
不是从源码推导出来的理论值——推导值放在 `docs/port-spec.md`，两者冲突时以本表为准。

## 0. 复刻口径（必须先统一）

| 项 | 值 | 依据 |
|---|---|---|
| 参考图像素 | 1144 × 1144 | `report/local-*.png` |
| 仪表 CSS 尺寸 | 572 × 572 px | `tools/artifacts.mjs:66` 强设 `#gauge-stage` 宽 572 |
| deviceScaleFactor | 2 | `tools/artifacts.mjs:48` |
| viewBox | 286 × 286 user unit (uu) | `src/gauge/tokens.ts` |
| **uu → 设备像素** | **×4.0** | 572×2 / 286 = 4 |
| 裁剪 | `#gauge-stage` 的 boundingBox 原样，pad = 0 | `artifacts.mjs:69-74` |
| URL 参数 | `?bare=1&static=<v>&stage=<s>`（扩展刻度加 `&scale=auto`） | `artifacts.mjs` |

因此 **Slint 侧对拍时：组件逻辑尺寸 572 px、scale factor 2 → 输出 1144 px 图**，
像素坐标 ÷ 4 即得 uu。`shots/*.png` 是另一套口径（440 CSS + pad 8 = 912 px），**不要混用**。

## 1. 圆环（radial scan @ r=130）

| 项 | 理论 | 实测（uu） | 说明 |
|---|---|---|---|
| 内半径 | 118.5 | 118.3 … 118.8 | 含 1 px 抗锯齿边，取 118.5 |
| 外半径 | 141.5 | 141.55 … 141.7 | 同上，取 141.5 |
| 环宽 | 23.0 | 23.0 … 23.2 | `stroke-width: 23` |
| 圆心 | (143, 143) | (143, 143) | — |

扫描角度 -60° / +60° 最干净（避开刻度文字墨迹）；在 0° / ±100° 处扫描会先打到刻度字（r≈93–104），
所以那些角度的内半径读数无意义，不要用。

## 2. 中央数字（Gauge Mono / 36 uu）

墨迹（ink）bbox 在各状态间**完全一致**，这是最强的一条回归断言：

| 状态 | 文本 | ink bbox (uu) | ink 中心 (uu) | ink 尺寸 (uu) |
|---|---|---|---|---|
| idle | `0.00` | 120.75, 207.25 → 165.00, 235.25 | (143.00, 221.38) | 44.50 × 28.25 |
| low (8 Mbps) | `8.00` | 120.50, 207.25 → 165.00, 235.25 | (142.88, 221.38) | 44.75 × 28.25 |
| mid (155.61) | `155.61` | 106.50, 208.00 → 179.25, 235.25 | (143.00, 221.75) | 73.00 × 27.50 |
| high (862) | `862.00` | 106.50, 207.25 → 179.00, 235.25 | (142.88, 221.38) | 72.75 × 28.25 |
| upload (341) | `341.00` | 106.50, 207.25 → 179.00, 235.25 | (142.88, 221.38) | 72.75 × 28.25 |
| extended (4200) | `4,200.00` | 100.00, 207.25 → 189.25, 237.75 | (144.75, 222.62) | 89.50 × 30.75 |

**关键结论**：SVG 锚点写的是 `y = 226`，但 ink 中心实测只有 **221.38**——比锚点高 4.6 uu。
这不是 bug：`dominant-baseline: central` 把**em 盒**中心对到 226，数字字形只占其上半部。
Slint 的 `Text` 在固定高度盒里居中同样是 em 盒居中，所以 **在 Slint 里把数字行盒中心放在 y=226、
不做任何 ink 补偿**，就能落到 221.4。若第一阶段渲染出来 ink 中心不是 221.4±0.5，
只允许用一个**标定常量 `number_dy`** 修正，并把实测差值写进 README。

字体实测（`tools/verify_fonts.py`）：`Gauge Mono` upm 2048、单数字推进 **0.389648 em** 完全等宽、
`.` = 0.179688 em、`"862.00"` = 2.127930 em、字重仅 400。
`0.389648 × 36 = 14.027 uu/数字`，`"862.00"` 推进 = 76.6 uu，墨迹 72.75 uu（侧边距 3.85 uu）——自洽。

## 3. 单位行（Montserrat Bold 14 uu + 16 uu 图标）

| 项 | 实测（uu） |
|---|---|
| 整行 ink bbox（download 图标） | x 115.25 … 170.00，y 252.50 … 267.50 |
| 整行 ink bbox（upload 图标） | x 115.25 … 170.00，y 254.50 … 267.50 |
| ink 中心 x | **142.75**（六个状态全同） |
| ink 中心 y | 260.12（download）/ 261.12（upload） |

- 行内 ink 宽度恒为 55.0 uu、`"Mbps"` 右边界恒为 170.0 uu ⇒ 水平定位与阶段无关。
- **横向不是"盒子居中"，而是"墨迹居中"**：图标 path 墨迹从 x=3.5 开始（16 宽的盒子里留了 3.5 空边），
  所以盒式居中的行会比参考整体**偏右 1.75 uu**。Slint 里用一个 286 宽、`x = -1.75` 的容器 + 居中
  `HorizontalLayout{ spacing: 4px }`（icon 16×16 + Text 14u）来复现，`unit-row-shift = -1.75`。
- upload 图标比 download 低 3 uu，这是源码里两条 path 的硬编码差异（`M6.6 0.6h…` vs `M6.6 15.4h…` 再 `translate(0,-8)`），
  **不要"对齐"它**，照抄即可。
- `"Mbps"` 推進 = 2.866 em × 14 = 40.12 uu（Montserrat Bold upm 1000 实测）。

## 4. 刻度文字（9 档，r = 97）

实测 **ink 中心**（uu），与 `labelAngleAt` 的极坐标锚点对比：

| 值 | 角度 | 锚点 x,y | 实测 ink 中心 | 差值 |
|---|---|---|---|---|
| 0 | −135° | 74.43, 211.57 | 74.40, 210.40 | (−0.03, −1.17) |
| 5 | −101.25° | 47.86, 161.85 | 47.80, 160.60 | (−0.06, −1.25) |
| 10 | −67.5° | 53.13, 104.63 | 53.10, 104.60 | (−0.03, −0.03) |
| 50 | −33.75° | 89.00, 61.13 | 89.00, 61.10 | (0.00, −0.03) |
| 100 | 0° | 143.00, 46.00 | 142.90, 44.90 | (−0.10, −1.10) |
| 250 | 33.75° | 197.00, 61.13 | 196.80, 61.10 | (−0.20, −0.03) |
| 500 | 67.5° | 232.87, 104.63 | 232.50, 104.60 | (−0.37, −0.03) |
| 750 | 101.25° | 238.14, 161.85 | 238.10, 160.60 | (−0.04, −1.25) |
| 1000 | 135° | 211.57, 211.57 | 211.40, 210.40 | (−0.17, −1.17) |

- 水平方向全部吻合在 0.4 uu 内（`text-anchor: middle` 按 advance 居中 ⇒ Slint 的
  `horizontal-alignment: center` 语义一致）。
- 垂直方向：只有 10/50/250/500 的 ink 中心≈锚点，其余约高 1.1–1.25 uu。
  这是因为表中那些"0 差值"的行恰好是**数字墨迹上下对称**的字符串（`10` 的 1 与 0 高度…）——
  以 **`100` 的 −1.10** 为准：Slint 里把 14 uu 文字的**行盒中心**放在锚点上即可复现，
  不需要逐档手工偏移。若偏差超过 0.5 uu，用统一常量 `label_dy` 修正。
- 字重必须是 **Bold(700)**：原 `montserrat.woff2` 是可变字体、默认实例是 Thin(100)，
  已用 `instantiateVariableFont(wght=700)` 生成静态 Bold 实例（`assets/fonts/montserrat.ttf`）。
  直接转换会得到 Thin，数字宽度会窄 4%–16%——这是最容易踩的坑。

## 5. 扩展刻度（auto，10 档 = 30°/档）

`local-extended.png` = `static=4200&download&scale=auto`：

- 10 个标签按 30° 等角分布：0(−135°)、10(−105°)、50(−75°)、100(−45°)、250(−15°)、
  500(+15°)、1000(+45°)、2500(+75°)、5000(+105°)、10000(+135°)。
- 实测 `250` ink 中心 (117.9, 49.3) 与 `500` (168.1, 49.3) ⇒ 确认 −15°/+15° 的 30° 步长，
  而不是 9 档的 33.75°。
- **`10000` 与中央数字 `4,200.00` 在视觉上重叠**（数字 ink 右边界 189.25，`10000` 左边界 ≈189）。
  这是原实现的真实产物，**必须保留**，不要为"好看"挪开。
- 亮起的刻度 = 2500 及以下；5000/10000 保持熄灭。

## 6. 亮弧终点（sweep end）——三方同步的硬指标

沿 r=130 按 0.05° 步长扫描"非轨道色"的最大角度：

| 状态 | 期望角度 | 实测 | 偏差 |
|---|---|---|---|
| idle | 无亮弧（sweep < 0.05° 直接隐藏） | `none` | ✓ |
| low (8 Mbps) | −81.000 | −80.90 | +0.10 |
| mid (155.61) | 12.512 | 12.45 | −0.06 |
| high (862) | 116.370 | 116.40 | +0.03 |
| upload (341) | 46.035 | 45.90 | −0.14 |
| extended (4200, auto) | 95.400 | 95.35 | −0.05 |

±0.14° ≈ ±1.3 px（@1144），全部落在抗锯齿/阈值误差内。**因此验收线定为：sweep 终点 |Δ| ≤ 0.2°**，
指针角度与亮弧终点必须同帧同角（同一 `displayAngle` 驱动）。

## 7. 其它可在像素上验证的断言

1. `report/local-done.png` 与 `report/local-high.png` **逐字节相同**（SHA256 `2977611231b9…`）。
   ⇒ done 阶段 = 下载变体 + 下载强调色 + 指针不回零 + 读数保持 862.00。
2. 轨道色 `#26273b`（luma ≈ 39），亮弧任一采样点 luma ≫ 60 ⇒ 上表的扫描阈值是安全的。
3. 背景纯黑 `#000000`；`local-idle` 全图非黑像素数 = 3630（数字）+ 2287（单位行）+ 各刻度（见 json）。
